# Кампус — интерфейс для fun-student

В проект встроен веб-интерфейс управления студентами и пользователями.
Светлая тема: кремовый фон, тёмно-зелёный текст, хвойный акцент и терракотовые детали.
Тёмная тема: глубокий зелёный фон, бежевый текст, шалфейные и песочные акценты.
Чистые белый и чёрный в палитре интерфейса не используются.

## Быстро посмотреть оформление

Откройте `preview.html` в обычном браузере. Нажмите «Посмотреть интерфейс».
Для демонстрации не нужны Java, PostgreSQL и интернет. В ней можно переключать темы и роли,
искать записи, открывать карточки, создавать, редактировать и удалять тестовые записи.
Это отдельные временные данные: после перезагрузки они сбрасываются и не отправляются на сервер.
Форма реального входа работает только в запущенном Spring Boot приложении.

## Запуск полного приложения в Windows

1. Установите JDK 21 и PostgreSQL. Убедитесь, что `java -version` и `javac -version` работают.
2. В pgAdmin или psql создайте базу:

   ```sql
   CREATE DATABASE students_db;
   ```

3. Откройте `src/main/resources/application.yml` и проверьте параметры PostgreSQL:

   ```yaml
   spring:
     datasource:
       url: jdbc:postgresql://localhost:5432/students_db
       username: postgres
       password: postgres
   ```

   Вставьте свои значения в уже существующие строки. Не добавляйте второй блок `spring`.
   Если ваш пароль отличается, замените его. PostgreSQL должен быть запущен.
   В исходном проекте настроено создание схемы students_schema и обновление таблиц.
4. Откройте PowerShell в папке проекта и выполните:

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

   Или откройте проект в IntelliJ IDEA как Maven-проект, выберите JDK 21 и запустите
   `StudentApplication`.
5. Дождитесь сообщения о запуске и откройте http://localhost:8080 в браузере.

При первом запуске Maven загружает зависимости из интернета. Отдельно ставить Maven или Node.js не требуется.
В Linux/macOS команда запуска: `./mvnw spring-boot:run`.
Чтобы остановить сервер в терминале, нажмите Ctrl+C.

### Если PostgreSQL ещё не установлен, но есть Docker

Вместо ручной установки PostgreSQL можно выполнить `docker compose up -d`.
Файл `compose.yaml` запускает только базу данных с параметрами исходного проекта.
Не используйте этот вариант одновременно с PostgreSQL, уже занимающим порт 5432.
После этого запустите Java-приложение обычной командой выше.

## Учётные записи для учебного запуска

Создаются исходным `AppInitializer` только если соответствующего email ещё нет:

| Email | Пароль | Роль |
|---|---|---|
| admin@example.com | admin | Работа со студентами |
| teacher@example.com | teacher | Просмотр студентов |
| superadmin@example.com | superAdmin | Управление пользователями |

Если в вашей базе уже есть эти пользователи, их существующие пароли не заменяются.
Это учебные учётные данные. Перед реальным размещением замените их и вынесите секрет JWT,
который остался в исходном `JwtService`, из исходников в защищённые настройки.

## Возможности интерфейса

- Вход по email и паролю с JWT; токен хранится только в sessionStorage текущей вкладки.
- Выход и обработка истечения сессии.
- Переключение светлой и тёмной тем; выбор сохраняется в браузере.
- Поиск по имени, фамилии и ID студента; поиск пользователей по email.
- Сортировка, постраничный просмотр, фильтр пользователей по роли.
- Карточка студента с контактами, добавление, изменение телефона/email, удаление с подтверждением.
- Создание пользователей, изменение email/ролей/пароля, удаление.
- Обработка загрузки, пустых результатов, ошибок сети и сервера.
- Адаптивная вёрстка для компьютера и телефона; диалоги и поля доступны с клавиатуры.
- Демонстрационный режим с переключением ролей.

Права исходного API сохранены. SUPER_ADMIN не наследует ADMIN: он управляет пользователями,
но не получает автоматически доступ к студентам. Для совмещения назначьте обе роли.
Преподаватель не видит кнопок изменения. Сервер дополнительно проверяет права каждого запроса.
Имя и фамилия студента при редактировании доступны только для чтения: исходный API обновляет только контакты.
Поиск и пагинация выполняются в браузере по загруженному списку, что подходит для учебного объёма данных.

## Где лежит интерфейс

- `src/main/resources/static/index.html` — страница и SVG-иконки.
- `src/main/resources/static/assets/styles.css` — обе палитры и адаптивная вёрстка.
- `src/main/resources/static/assets/app.js` — экраны, формы, поиск, темы, работа с API и демо.
- `src/main/resources/static/assets/favicon.svg` — значок приложения.
- `preview.html` — автономная копия для знакомства с дизайном; источником правок остаются файлы в static.

Интерфейс и API работают на одном адресе. CORS и отдельный frontend-сервер не нужны.
Внешние шрифты, CDN и библиотеки JavaScript не используются.

## Исправления сервера для интеграции

- Разрешено открывать главную страницу и assets без входа; API остаётся защищённым.
- Добавлены JSON-ответы 401/403 и понятная обработка ошибок входа, валидации и конфликта email.
- Исправлено обновление пользователя: теперь используется ID из URL и возвращается UserResponse.
- Пустой пароль при обновлении сохраняет старый; при создании пароль обязателен.
- Добавлена проверка обязательных полей, email, длины строк и ролей.
- JWT-фильтр возвращает нейтральное сообщение вместо внутренних сведений об исключении.

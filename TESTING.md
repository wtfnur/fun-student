# Тесты и покрытие

## Быстрый запуск в Windows

Откройте PowerShell в папке, где лежат `pom.xml` и `mvnw.cmd`:

```powershell
.\mvnw.cmd clean verify
```

Дождитесь `BUILD SUCCESS`. Затем откройте свежий отчёт:

```powershell
Start-Process .\target\site\jacoco\index.html
```

Для запуска необходим JDK 21. Если Java видна только в текущем окне PowerShell,
запускайте тесты из него. Для известной установки JDK можно выбрать его так:

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\mvnw.cmd clean verify
```

Используйте фактическую папку установленного JDK, если она отличается.
При первом запуске нужен интернет для загрузки инструментов Maven.
Отдельно устанавливать JUnit, Mockito, H2 и JaCoCo не требуется.
В Linux/macOS команда: `./mvnw clean verify`.

## Результат выполненной проверки

Команда `clean verify` выполнена 13 ноября 2026 года на JDK 21.0.2.
Все 52 тестовых сценария прошли: 0 ошибок, 0 неуспешных проверок, 0 пропусков.
Параметризованные случаи учитываются как отдельные сценарии.

| Метрика Java-кода | Покрыто | Всего | Покрытие |
|---|---:|---:|---:|
| Строки | 247 | 254 | 97,24% |
| Ветвления | 50 | 54 | 92,59% |
| Инструкции байткода | 1079 | 1110 | 97,21% |

В `pom.xml` установлены два общих порога JaCoCo: минимум 75% строк
и минимум 75% ветвлений. Если хотя бы один показатель ниже порога,
обычная сборка `verify` завершится ошибкой. Проверка применяется ко всему
Java-модулю в целом, а не к каждому классу отдельно.
Никакие пакеты или классы приложения вручную из покрытия не исключены.
Стандартный фильтр JaCoCo не учитывает методы, помеченные генератором Lombok
как сгенерированные. HTML, CSS и JavaScript интерфейса JaCoCo не измеряет.

## Какие тесты добавлены

| Класс | Сценариев |

- `InterfaceIntegrationTest`: реальный HTTP-сервер, вход, доступность интерфейса,
  три роли, ограничения доступа, операции со студентами и пользователями,
  валидация запросов, повреждённый JSON, конфликт email, HTTP 400/401/403/404/409.
- `UserServiceTest`: регистрация, поиск, списки, хеширование пароля, дубли email,
  обновление по ID, изменение ролей, сохранение старого пароля при пустом поле,
  отклонение недопустимой длины нового пароля.
- `StudentServiceTest`: сохранение неизменённых полей при частичном обновлении,
  очистка контактов, отсутствующие записи, полная карточка, пустой список.
- `JwtServiceTest`: подписанные токены, имя пользователя, роли, несовпадение
  пользователя, повреждение подписи и некорректный токен.
- `JwtFilterTest`: обработка заголовка Authorization, текущие права пользователя,
  истёкший токен, удалённый пользователь, отсутствие или неуспешная авторизация.

Тесты лежат в `src/test/java/com/example/student`.
В `src/test/resources/mockito-extensions/org.mockito.plugins.MockMaker`
выбран `mock-maker-subclass`: этим тестам не требуется динамическое подключение
Mockito-агента к JVM.

## Ваша база данных не затрагивается

Для интеграционных тестов используется отдельная H2-база в памяти в режиме
совместимости с PostgreSQL. Её настройки указаны прямо в аннотации тестового класса
и имеют приоритет над обычными переменными подключения приложения.
PostgreSQL не требуется запускать, создавать другую БД или менять пароль не нужно.
Тесты используют случайный HTTP-порт и не занимают порт 8080.
Настоящее приложение может продолжать работать параллельно.

Это проверяет приложение и JPA на H2; специфическое поведение PostgreSQL такая
проверка не заменяет. Отдельных тестов frontend JavaScript в этом наборе нет.

## Где смотреть отчёты

- `coverage-report/index.html` — сохранённый отчёт проверки, вложенный в архив.
  Можно открыть сразу после распаковки, без запуска Maven.
- `target/site/jacoco/index.html` — свежий отчёт после вашего запуска тестов.
- `target/site/jacoco/jacoco.xml` и `jacoco.csv` — метрики для автоматической обработки.
- `target/surefire-reports` — результаты отдельных тестов после запуска.

На главной странице JaCoCo можно переходить в пакеты и классы, затем открывать
исходники. Зелёные строки выполнены тестами, красные не выполнены,
жёлтые содержат частично проверенные инструкции или условия.
Для требования 75% ориентируйтесь на `Total` и колонки `Cov.`: строки и ветвления.

`mvnw.cmd test` запускает тесты и формирует отчёт, но порог проверяется именно
на фазе `verify`. Используйте `clean verify`, чтобы удалить старые результаты
и получить заново измеренное покрытие.
